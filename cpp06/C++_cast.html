Les différents types de cast en C++

Guide complet des conversions de types

1️⃣ Cast implicite (Implicit Cast)

Description

Effectué automatiquement par le compilateur sans intervention du programmeur.

Caractéristiques

  • Conversions sûres et sans perte d'information (généralement)
  • Entre types compatibles
  • Effectué automatiquement lors d'une assignation ou appel de fonction

Exemples

int i = 5; double d = i; // int → double (implicite) float f = 3.14f; double d2 = f; // float → double (implicite) void print(double x) { std::cout << x; } print(5); // int → double (implicite)

2️⃣ static_cast

Description

Cast de compilation sûr pour les conversions entre types compatibles.

Caractéristiques

  • Conversions entre types numériques
  • Pointeurs dans une hiérarchie de classes
  • Pointeur void vers autre type
  • Pas de vérification à l'exécution

Champ d'application

  • Conversions numériques explicites
  • Conversions haut/bas dans une hiérarchie de classes (moins sûr que dynamic_cast)
  • Convertir pointeur void en type spécifique

Exemples

double d = 3.14; int i = static_cast(d); // double → int class Animal {}; class Dog : public Animal {}; Animal* animal = new Dog(); Dog* dog = static_cast(animal); // conversion haut vers bas (risquée!) void* ptr = malloc(100); int* iPtr = static_cast(ptr); // void* → int*

3️⃣ dynamic_cast

Description

Cast sûr pour les conversions polymorphes avec vérification à l'exécution.

Caractéristiques

  • Fonctionne uniquement avec des classes ayant au moins une fonction virtuelle
  • Vérification de type à l'exécution
  • Retourne nullptr en cas d'échec (pour les pointeurs)
  • Lève une exception std::bad_cast pour les références
  • Légèrement plus coûteux que static_cast

Champ d'application

  • Conversion sûre haut/bas dans une hiérarchie de classes
  • Vérifier si un objet est d'un type spécifique
  • À privilégier pour les conversions polymorphes

Exemples

class Animal { public: virtual ~Animal() {} }; class Dog : public Animal {}; class Cat : public Animal {}; Animal* animal = new Dog(); Dog* dog = dynamic_cast(animal); // OK, retourne non-null Cat* cat = dynamic_cast(animal); // retourne nullptr // Avec une référence Animal& ref = *animal; Dog& dogRef = dynamic_cast(ref); // OK Cat& catRef = dynamic_cast(ref); // Lance std::bad_cast

4️⃣ reinterpret_cast

Description

Cast dangereux pour les conversions entre types incompatibles.

Caractéristiques

  • Réinterprète la représentation binaire sans conversion
  • Très peu de vérifications de sécurité
  • Convertir entre n'importe quels types de pointeurs
  • Peut convertir en entier et inversement
  • À utiliser avec prudence

Champ d'application

  • Opérations bas niveau (hardware, drivers)
  • Sérialisation/désérialisation
  • Interopérabilité C/C++
  • À éviter autant que possible

Exemples

int* intPtr = new int(42); void* voidPtr = reinterpret_cast(intPtr); double* doublePtr = reinterpret_cast(intPtr); // DANGEREUX! // Convertir adresse en entier uintptr_t addr = reinterpret_cast(intPtr); // Pas de conversion, c'est une réinterprétation struct A { int x; }; struct B { int x; }; A a; B& b = reinterpret_cast(a); // Les bits sont réinterprétés comme B

5️⃣ const_cast

Description

Cast pour ajouter ou enlever la qualité const/volatile.

Caractéristiques

  • Seul le cast capable de modifier la qualité const/volatile
  • Ne change pas la représentation binaire
  • Tous les autres casts ne peuvent pas enlever const
  • À utiliser judicieusement

Champ d'application

  • Travailler avec une API C qui n'est pas const-correct
  • Appeler une fonction non-const à partir d'une méthode const
  • Enlever volatile

Exemples

const int* constPtr = new int(10); int* ptr = const_cast(constPtr); // enlever const *ptr = 20; // modification possible const int x = 5; int& xRef = const_cast(x); // enlever const xRef = 10; // UB! x était vraiment const void readFile(char* buffer); // API C non const-correct void processData(const char* data) { readFile(const_cast(data)); // cas d'usage valide }

📊 Tableau récapitulatif

Type Sûr Vérification Cas d'usage
Implicite Très sûr À la compilation Conversions compatibles
static_cast Sûr À la compilation Conversions numériques, hiérarchie de classes
dynamic_cast Très sûr À l'exécution Polymorphisme, vérifier le type
reinterpret_cast Dangereux Aucune Bas niveau, opérations hardware
const_cast Sûr À la compilation Enlever const/volatile

💡 Bonnes pratiques

✅ À faire

  • Préférer dynamic_cast pour les conversions polymorphes
  • Utiliser static_cast pour les conversions explicites et sûres
  • const_cast seulement si vraiment nécessaire

❌ À éviter

  • Abuser de reinterpret_cast
  • Utiliser const_cast pour contourner la sécurité du code
  • Cast trop fréquents (signe d'un mauvais design)
